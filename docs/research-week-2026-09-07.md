# What changed this week that can make the box faster (scan of 2026-08-27 .. 09-07)

Sources are linked inline. Everything here is a lead until it is measured on
the box; the measurement for each is one line.

## 1. Drafters that work with llama-server today - and the fork cannot run them

Speculation died on this box because the shipped MTP head agrees with the
DavidAU merge 7-11% of the time. Two things changed that picture:

**DSpark drafters for Qwen3.8-27B exist as GGUF and run in upstream
llama-server.** DSpark (DeepSeek/PKU) is DFlash plus a Markov head; the drafter
conditions on the target's residual stream at five layers, not on the trunk's
last hidden state alone, which is why it transfers across quantizations of the
same target unchanged.

- [DimInfer/Qwen3.8-27B-Dspark-v1](https://hf.co/DimInfer/Qwen3.8-27B-Dspark-v1):
  trained against the served **Q4_K_M GGUF** of base Qwen3.8-27B. One RTX
  4090D, llama.cpp, temperature 0: baseline 48.9 -> **83-123 tok/s (1.69-2.51x)**,
  accepted length 2.7-4.1; peak at `--spec-draft-n-max 4`. Q8_0 drafter 2.0 GB.
  Recipe published in outline: 40K prompts regenerated by the served target,
  hidden states captured from the GGUF, 936 steps on 4x 4090D, warm-started
  from their Qwen3.6 head. **That recipe is how a head gets aligned to the
  DavidAU merge if the base heads do not transfer.**
- [RadixArk/Qwen3.8-27B-DSpark](https://hf.co/RadixArk/Qwen3.8-27B-DSpark) (v2:
  accepted length 3.4 across 17 workloads; 2.25-3.16x at concurrency 1 on
  SGLang). Repackaged as GGUF next to *our exact merge* in
  [Solstice-AI/...-GGUF-UltraOptimised-DSpark](https://hf.co/Solstice-AI/Qwen3.8-27B-TURBO-Fable-Cold-Fusion-735-882-Heretic-Uncensored-GGUF-UltraOptimised-DSpark)
  (`speculative/Qwen3.8-27B-DSpark-Q8_0.gguf`, 1.98 GB). Note: it is the
  base-target head; the card's 2.5-3.1x is RadixArk's base-model number.
- [z-lab/Qwen3.8-27B-DFlash2-GGUF](https://hf.co/z-lab/Qwen3.8-27B-DFlash2-GGUF)
  (Aug 2026): accepted length 5.1-5.4 on base Q4_K_M at xhigh reasoning;
  `--spec-type draft-dflash --spec-draft-n-max 7`; needs upstream
  [#27342](https://github.com/ggml-org/llama.cpp/pull/27342) (merged Aug 27).

**The fork cannot run any of them.** `common/speculative.cpp` was last touched
2026-07-23 (a port of the PrismML fork) and its own comment says `draft-dspark`
"fails at the first draft round" in server/CLI because capture is not engaged.
Upstream merged full server support on **July 28**
([#25173](https://github.com/ggml-org/llama.cpp/pull/25173)); DFlash2 GGUFs need
the post-Aug-27 loader. The fork's ggml-cuda, KV cache and server code are all
six weeks behind master.

**The fork's MTP result is suspect for the same reason.** DavidAU's own card
reports ~60% acceptance at 2 drafted tokens on these exact MTP GGUFs (75 -> 90+
tok/s on a 5090 in LM Studio, i.e. upstream llama.cpp); a community run on base
Qwen3.8 shows 71.6% overall acceptance and 23.7 -> 50.7 tok/s at n-max 3
([mrchuy](https://hf.co/mrchuy/Qwen3.8-27B-DFlash-drafter-bootstrap-GGUF)). The
box measured 7-11% on a fork whose MTP path carries a custom d2t draft-vocab
trim (8f2dbea) over the July port. Until the same file is run on upstream, "MTP
does not work on this model" is a claim about the fork, not the model.

## 2. Upstream llama.cpp changes since the fork's base that hit this box directly

| PR | merged | why it matters here |
| --- | --- | --- |
| [#27991](https://github.com/ggml-org/llama.cpp/pull/27991) kv cache: optimize restoring non-contiguous cells | Aug 31 | prompt-cache restore in "agentic multi-turn tool-calling with parallel requests and unified KV" - Hercules' exact shape - went from 25-63 s to 0.2-0.4 s per restore (~100x) |
| [#26705](https://github.com/ggml-org/llama.cpp/pull/26705) CUDA: branchless Q4_K/Q5_K unpack in mmvq | Sep 7 | +13-16% decode at batch 4-8 on Q4_K; moves the MMVQ->MMQ switch point |
| [#28208](https://github.com/ggml-org/llama.cpp/pull/28208) explicit recurrent_layers for Qwen3-Next/3.5 | Sep 7 | correct hybrid layer typing from GGUF metadata (uniform 16-of-64 was fine by interval; non-uniform merges were not) |
| [#25173](https://github.com/ggml-org/llama.cpp/pull/25173) DSpark | Jul 28 | see above |
| [#27342](https://github.com/ggml-org/llama.cpp/pull/27342) DFlash2 | Aug 27 | see above |

Two more from the OpenCode session's scan: [hanxiao/L4](https://github.com/hanxiao)
routes speculative verification to the MMQ tensor cores with a per-width
threshold (+16% at width 3+) - this fork now has the same knob as
`GGML_CUDA_MMVQ_MAX`; and Qwen's own fused GDN kernels (FlashQLA) are
sm_90+ only, so the 170HX's GDN cost is a missing Ampere kernel, not a
hardware limit. KGP Talkie's 45-config sweep on a 5090 gives the healthy-head
MTP acceptance curve (0.86/0.77/0.67 by position, optimum n-max 3) and finds
q4_0 KV fastest *there* (136.7 vs q8_0 128.3) - on sm_80 that comparison is
confounded by the quantized-KV vector-kernel path (`benches/`), so it does not
transfer without the f16-KV measurement.

Adaptive draft length (`--spec-draft-adaptive`, a
[fork](https://github.com/LaurentZuijdwijk/llama.cpp), not upstream) keeps
acceptance at 96% where a fixed n=7 collapses to 18%; relevant once a drafter
works.

## 3. Hermes Agent v0.21.0 (Aug 31) changed two defaults that size the server

- `delegation.max_concurrent_children` default is now **10** (was 3). With 4
  slots, set it to 3 explicitly or accept queueing.
- `model_overrides` can patch the context window per model. Hercules compresses
  at 50% of the window it believes the model has; if the custom provider
  defaults low, compression (and the prompt-cache invalidation it causes) fires
  far earlier than 131K. Set the override to 262144.
- v0.20 added per-turn micro-compaction and proactive tool-result pruning. If
  those rewrite earlier messages, every turn is a prefix change and a full
  re-prefill (~70 s on a 60K context at 855 tok/s). Verify by watching
  `prompt_cache` hits in the server log across a Hercules session.

## 4. CMP 170HX wiki (corpus frozen 2026-07-28; nothing newer)

- `nvidia-smi -lmc` is refused by the driver; memory VF offset range is
  `[0..0]`. The "steer power into HBM" idea is dead.
- INT8 tensor MMA measured 335 TOPS; FP16 159-190 TFLOPS - consistent with the
  box's 162-170.
- Community llama.cpp Qwen 27B Q4_K_M single stream: 36.9 tok/s on an unlocked
  card. The box's 33.5 is at parity; the remaining gap is llama.cpp's, not the
  unlock's.
- Power-limiting to 150 W "cost no measured throughput" in their stress tests.

## Test plan, cheapest first

1. **Build upstream master alongside the fork** (`git clone ggml-org/llama.cpp`,
   normal sm_80 build). Same DavidAU MTP GGUF, `--spec-type draft-mtp
   --spec-draft-n-max 2`, temp 1.0, one slot. If acceptance is ~60% as DavidAU
   reports, the fork's MTP path is broken and speculation was never dead.
2. On that upstream build: `-md Qwen3.8-27B-DSpark-Q8_0.gguf --spec-type
   draft-dspark --spec-draft-n-max 4 -ngld 99` (DimInfer head, then RadixArk's
   via Solstice). Report accepted length and tok/s. Base-target heads on the
   merged trunk: unknown, and this is the 10-minute answer.
3. If (2) is under ~2.5 accepted length, the DimInfer recipe with the DavidAU
   Q4_K_M as the target is the way to a matched head - 40K regenerated prompts,
   hidden-state capture from the served GGUF, hours on consumer GPUs.
4. Sync the fork to upstream master regardless (#27991 alone is worth it for
   Hercules), re-running the box measurements after.
5. Hercules config: `delegation.max_concurrent_children: 3`, `model_overrides`
   context 262144; watch prompt-cache hit rate for a session.
